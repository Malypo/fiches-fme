Readers, writers et feature types

1Les définitions

Workspace
L'élément principal d'une traduction FME : il stocke sa définition et contient toutes ses fonctions. Il ne stocke pas les données (seulement chemins, URL, connexions). Pour inclure les données, enregistre-le comme template.
Reader / Writer
Le composant qui lit un dataset source / qui écrit vers un dataset de destination.
Feature type
Décrit un sous-ensemble d'enregistrements : couche, table, feuille, feature class. Il apparaît sur le canevas.
Feature
Le plus petit composant d'une traduction : une ligne, une pièce de géométrie dans la Visual Preview.
Hiérarchie
1 workspace, plusieurs readers et writers, plusieurs feature types, plusieurs features.

2Prototyper et développer par étapes

Prototyper

Créer une application incomplète pour évaluer la faisabilité, puis construire un projet complexe par étapes.

Le développement incrémental

1. Découpe le projet en petites sections (un bookmark).
2. Construis une section (3 à 10 transformers : au-delà de 10, découpe).
3. Teste-la tout de suite, pour trouver les problèmes tôt.
4. Recommence en enregistrant et en testant.

Un petit échantillon de données

Extrais-le de la source avec un Tiler (raster), un Sampler ou un Tester.

Le versionnage

Avec un seul workspace modifié en continu, on ne retrouve pas ce qui a changé, on crée mal des versions par plateforme, et un workspace perdu ou corrompu est un projet perdu. Versionne le workspace (à la main ou avec Git) et tout le matériel du projet : fichiers Python, logs, dataset source (sans mot de passe).

Garder l'historique

L'outil Compare Workspace de FME Workbench, Git, le contrôle de version de FME Flow, la date dans le nom du fichier, un numéro de version dans un bookmark ou une annotation, ou Overview and History dans les Workspace Parameters.

3Gérer les features rejetées

Features rejetées

Des données qui échouent au traitement (par exemple une feature sans géométrie dans un AreaBuilder). Beaucoup de transformers ont un port Rejected. Un cercle rouge avec un nombre apparaît sur le port : inspecte-le.

Le réglage du workspace

Navigator, Workspace Parameters, Rejected Feature Handling : Terminate Translation ou Continue Translation. En mode terminate, la feature rejetée est écrite dans le log, avec un message d'erreur lié au transformer. En mode continue, le port Rejected compte les features rejetées.

Le mode mixte

En mode terminate, si le port Rejected est relié à un objet (un Logger, par exemple), le workspace ne s'arrête pas. Certains transformers peuvent donc stopper la traduction pendant que d'autres traitent la feature autrement.

4Ajouter, importer et mettre à jour

Ajouter des readers et writers

FME lit et écrit avec plusieurs readers, plusieurs writers ou les deux, avec les transformers FeatureReader et FeatureWriter, ou avec des transformers d'intégration (DropboxConnector, Emailer, HTTPCaller). Pas de nombre égal exigé, ni de limite de formats. Par Quick Add, par le menu Readers/Writers, Add, ou en glissant un fichier : le format se remplit alors avec l'extension.

Supprimer et mettre à jour un reader

Suppression par le menu ou par clic droit dans le Navigator. Mise à jour : clic droit dans le Navigator puis Update, ou menu Reader, Update. Pour lire tous les feature types même s'ils changent, utilise Merge feature types dans le dialogue Feature Type.

Importer des feature types

Ajoute un feature type à un dataset existant en important le schéma d'un autre dataset, comme un nouveau reader, sans tout régler de nouveau.

Mettre à jour ou supprimer un feature type

Reader/Writer, Update Feature Type, quand le schéma ou le type d'un attribut change. Suppression par clic droit sur le canevas. Si tu supprimes le dernier, FME propose de supprimer le reader ou le writer.

Quelle action pour quel cas ?

Nouvelle base avec un nouveau schéma : Writer Update. Nouvel attribut dans une source : Reader Update. Nouveau feature type d'un reader existant : Import Feature Types.

5Régler les paramètres

Paramètres de reader et de writer

Ils se règlent en ajoutant le reader ou le writer, dans le Navigator ou, pour le writer, sur le petit bouton au-dessus. Certains paramètres de reader ne se règlent qu'à l'ajout, car ils changent la génération des feature types : supprime et rajoute le reader pour les changer (par exemple Group Entities By pour AutoCAD DWG/DXF). Les feature types ont aussi leurs paramètres.

Compatibilité entre systèmes d'exploitation

Utilise le reader Directory and File Pathnames et les paramètres utilisateur FME pour les chemins. Évite les caractères non imprimables et la dépendance à la casse.

6Exercice : mettre à jour un parc

Exclure un parc

Filtre-le, ou ajoute une clause WHERE dans le reader.

Le GML en pretty print

Par le Navigator, dans les paramètres de tous les writers. Tu vérifies avec un éditeur de texte.

Fusionner le nom autochtone et le nom anglais

Décocher Overwrite database
Feature Operation : fme_db_operation, use existing
Row Selection : Match columns, ID unique (OBJECTID)
AttributeCreator : fme_db_operation = UPDATE, ParkName = nouveau nom

Il faut trouver et modifier une feature dans la base SQLite des parcs, sans en créer une nouvelle. Ajoute un Tester et déconnecte-le du writer pour mettre à jour à la main le parc concerné. Seul ce parc est mis à jour, les autres restent inchangés.

Le piège

Une feature non rejetée n'est pas forcément juste à 100 %. FME ne rejette que sur des problèmes précis.

Les chemins écrits en dur posent des problèmes de compatibilité entre systèmes d'exploitation.

À retenir

  • Un workspace ne stocke pas les données, seulement chemins et connexions.
  • Construis par sections de 3 à 10 transformers, et teste chacune.
  • Versionne le workspace et tout le matériel du projet.
  • Terminate ou Continue : choisis comment traiter les features rejetées.
  • Update, Import, Add : trois actions selon ce qui change dans le schéma.

Du prototype au workspace propre : un pas après l'autre.
