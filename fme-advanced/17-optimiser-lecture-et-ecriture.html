FME

Lire et écrire

Minimiser les données lues, ordonner les writers

1Les définitions

Search envelope
Une zone géographique qui limite la lecture (readers de données spatiales seulement).
Order Writers By
Le paramètre du workspace qui décide dans quel ordre les writers écrivent.

2Optimiser la lecture

La règle

La meilleure méthode : minimiser la quantité de données lues. Mauvais : lire des features en plus, et la mise en cache des features.

Filtrer en entrée

Navigator, reader, Parameters, Features to Read (Start Feature, Max, Min, Feature Types to Read). Exemple : si les premiers enregistrements commencent par C, on ne lit que les 419 premiers. Le Search envelope lit une zone géographique, très efficace sur des données indexées. Dans un FeatureReader, Clip to Initiator améliore la lecture avec la géométrie de l'initiator. Pour une base de données, la WHERE clause aide aussi.

Un paramètre de reader pour filtrer la source est plus efficace. Mettre en cache le feature type du reader n'aide pas forcément. Les transformers SQL sont plus performants que les readers. Le DatabaseQuerier unifie SQL et NoSQL et remplace SQLExecutor et SQLCreator.

Les feature types en trop

Souvent avec les listes de tables : on lit plus de tables ou couches de la geodatabase que nécessaire. Nettoyer avec Run, Remove, Unattached.

3L'ordre des readers

La règle

FME lit les features dans l'ordre du Navigator. L'ordre des writers compte plus que celui des readers.

Les exceptions

Un Creator qui déclenche un FeatureReader ou un autre transformer qui lit : le paramètre Create After Readers contrôle le comportement. Les problèmes de timing avec un transformer à groupes ou bloquant, bloqué en attendant un reader plus bas dans le Navigator. Le FeatureHolder arrête les features dans le workspace.

4Optimiser l'écriture

Le système de fichiers

Un disque rapide et réactif (SSD), un système d'exploitation pas occupé à écrire d'autres fichiers. Avec des RAID, certaines configurations demandent plusieurs écritures et ralentissent.

La base de données

Index et jointures existants ralentissent l'écriture. Plus rapide : supprimer l'index, écrire les données, le recréer.

Plusieurs writers

Celui qui reçoit le plus de données doit écrire en premier : il démarre quand il est prêt, les autres mettent en cache, donc le plus gros a le moins de données en cache. Le nombre de features approxime la taille, mais peut varier beaucoup : il faut connaître la taille.

L'ordre

Navigator : le premier de la liste écrit en premier, on les déplace
Order Writers By : Position in Workbench Navigator, ou First Feature Written (le writer qui reçoit la première feature démarre)

À retenir

  • Lis le moins possible : Features to Read, search envelope, WHERE clause.
  • Run, Remove, Unattached retire les feature types sans connexion.
  • L'ordre des writers compte plus que celui des readers.
  • Le plus gros writer en premier dans le Navigator.
  • En base : supprimer l'index, écrire, le recréer.
