Fanouts

Écrire par groupes de features

1Les définitions

Fanout
Un réglage de writer ou de feature type de writer : les données sont écrites par groupes de features.
Feature type fanout
Les groupes vont vers plusieurs feature types (couches, tables) d'un même dataset.
Dataset fanout
Les groupes vont vers le même feature type, mais dans plusieurs datasets.

2Le principe

Comment ça marche

Les groupes se définissent par la valeur d'un attribut, ou par une chaîne construite avec des attributs et du texte fixe. Pas besoin de plusieurs flux de données : ça se passe au moment de l'écriture, avec peu d'impact sur le canevas.

3Le fanout de feature types

Le résultat

Une couche par valeur, par exemple une couche par altitude dans un DWF.

Le réglage

Ce n'est pas un réglage à part. On choisit un attribut pour le nom du feature type du writer : le nom change selon la valeur de l'attribut.

4Le fanout de datasets

Le résultat

Plusieurs DXF, chacun avec une altitude.

Le réglage

Dans le Navigator, paramètre du dataset du writer. Par défaut, le fanout expression est le nom de fichier du chemin de destination : ce n'est pas un fanout. Pour en faire un, on met un attribut dans le fanout expression. L'éditeur de texte permet d'ajouter des paramètres utilisateur, des fonctions, des dates.

5Fanout et zip

Les trois cas

Un seul zip : destination fanout directory = fichier zip
Plusieurs zips : le zip dans le fanout expression
Plusieurs zips dans un zip : les deux techniques combinées

Pratique pour les formats à plusieurs fichiers (shapefile) ou les gros jeux de données (raster).

On peut combiner un fanout de datasets et un fanout de feature types dans le même writer.

6Exercice : le community map

Le but

Donner à l'utilisateur une couche ou un fichier par feature type, dans un zip, puis découper chaque couche en quatre quadrants.

Les étapes

Feature type fanout sur fme_feature_type
Extension .zip sur la destination générique
Tiler par nombre (2 x 2)
Fanout expression : CommunityMapping.zip\@Value(_column)x@Value(_row)\

Le reader est configuré pour fusionner toutes les entrées. fme_feature_type garde la couche d'origine.

Le format Generic laisse l'utilisateur choisir le format, avec un paramètre OutputFormat dans les User Parameters. FME ne peut jamais écrire plus d'un type de géométrie dans le même shapefile : on ajoute point, ligne ou polygone à la fin du nom.

Le piège

Un fanout vers un shapefile qui mélange les géométries ne fonctionne pas : un shapefile ne contient qu'un seul type de géométrie.

À retenir

  • Un fanout écrit par groupes de features sans multiplier les flux.
  • Feature type fanout : plusieurs couches dans un dataset.
  • Dataset fanout : plusieurs datasets, il se règle dans le Navigator.
  • Écrire .zip suffit à zipper la sortie, y compris avec un fanout.
  • fme_feature_type renvoie chaque feature à sa couche d'origine.

Un fanout bien placé évite dix writers sur le canevas.
