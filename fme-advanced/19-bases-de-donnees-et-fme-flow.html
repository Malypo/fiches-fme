DatabaseQuerier, transactions et engines

1Les définitions

Features Per Bulk Write
Le nombre de features que FME met en cache avant de les envoyer à la base.
Features Per Transaction
Le nombre de features envoyées avant que FME ordonne le commit (Transaction Interval).
Scalabilité
Augmenter la charge ou le volume sans perdre en performance, en faisant varier les ressources.

2Lire une base de données

Les outils

Filtrer en base avec ses fonctions natives (WHERE) est plus rapide. Le DatabaseQuerier unifie SQL et NoSQL et autorise des requêtes complexes.

Les deux modes

Run Once : une requête qui génère des features, sans port d'entrée
Input driven : une requête par feature entrante, avec un port initiator comme le FeatureReader

Le DatabaseJoiner et le FeatureReader

Le DatabaseJoiner convient pour récupérer des attributs à attacher à la feature entrante. Le FeatureReader évite d'écrire du SQL (l'assistant IA peut aider) et se comporte comme un reader piloté par l'entrée, mais plus générique, donc plus lent.

Exposer les attributs

Avec le DatabaseQuerier, les attributs ne sont pas exposés : FME ne connaît pas leurs noms et types avant la requête. Bouton à côté de l'attribut : saisie manuelle ou Populate from Query.

SQLCreator ou SQLExecutor restent les meilleurs pour lire des features issues de la jointure de deux tables avec une condition sur un attribut.

3Écrire en base

L'équilibre

Données et nombre de requêtes (trafic réseau)
Données stockées par FME en attente de transfert (performance FME)
Données stockées en base en attente de commit (performance de la base)
Risque de perdre des données non commitées

Features Per Bulk Write

Valeur numérique : les features sont mises en cache en mémoire jusqu'à cette taille de chunk, puis envoyées. Plus haut : FME met plus en cache, moins de requêtes, moins de trafic. Plus bas : moins de cache, plus de requêtes, plus de trafic.

Features Per Transaction

Les features envoyées sont en cache dans la mémoire de la base. Quand le nombre est atteint, FME envoie la commande de commit, et chaque commit retarde l'écriture. À 1, chaque feature est commitée individuellement : en cas d'échec, seule la dernière est perdue, mais c'est plus lent. Très haut (plus que le nombre de features), un seul commit : en cas d'échec, tout est perdu.

Les deux ensemble

Transaction inférieur ou égal à Bulk Write : FME met en cache plusieurs features et les envoie avec un commit immédiat. Transaction supérieur à Bulk Write : FME envoie les features à la base, qui les garde en cache jusqu'au total de commit.

Index et tables

Les index accélèrent la lecture mais ralentissent l'écriture : la base les met à jour feature par feature, indépendamment des intervalles de commit. Supprimer les index avant un bulk insert, dans la base ou avec un SQLExecutor. Dans le writer, supprimer (drop) une table est plus efficace que la vider (truncate) car on retire les index. Désactiver la connectivité réseau pendant l'écriture dans un geometric network d'une Geodatabase.

5FME Flow

La scalabilité

Le plus simple à augmenter : le nombre d'engines, pour un plus grand volume de jobs. Le Core contient un Software Load Balancer (SLB) qui répartit les jobs entre engines. FME Flow exécute un job par engine à la fois.

Les traductions en masse

Par défaut, utiliser plusieurs engines n'est possible que s'il y a plusieurs workspaces à lancer. Pour un seul workspace, il faut le diviser en plusieurs jobs : un workspace parent qui divise les données et envoie chaque partie à un job worker avec le FMEFlowJobSubmitter.

Les engines CPU-usage

Un modèle d'engines facturés à l'usage : on monte plusieurs engines et on paie le temps CPU, pas par engine. Pertinent quand il y a beaucoup de données à traiter, mais pas souvent.

FME Flow Hosted

Pas d'achat de FME Flow, on l'utilise quand un job en profite. On crée une instance avec autant d'engines qu'on veut (le matériel choisi joue). On automatise avec un custom transformer du Hub, comme le FMEFlowHostedInstanceLauncher ou FMEFlowHostedInstanceController : le parent démarre l'instance et lance un ou plusieurs jobs worker. Une nouvelle instance par job ou plusieurs jobs sur une, selon le type d'instance et son nombre d'engines. Le nombre d'engines disponibles est illimité.

À retenir

  • DatabaseQuerier : Run Once ou Input driven, attributs à exposer.
  • Bulk Write contrôle le cache de FME, Transaction contrôle le commit de la base.
  • Supprime les index avant un gros insert et recrée-les.
  • Drop est plus efficace que truncate, car il retire les index.
  • Sur FME Flow, un job par engine : divise un gros workspace en plusieurs jobs.
