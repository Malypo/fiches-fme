1Les définitions

Glob expression
Une façon d'écrire un chemin de manière dynamique, avec des jokers.
Merge Feature Types
Lire plusieurs feature types comme un seul.

2Pourquoi plusieurs

Les besoins

Une intégration de données rassemble des jeux dans différents formats. On sépare la sortie par fonction, utilisateur ou langue. On isole les données de mauvaise qualité pour un contrôle automatique ou manuel. On crée vite beaucoup de couches ou de tables.

Les outils

Plusieurs readers ou writers
FeatureReader, FeatureWriter
Transformers d'intégration (DropboxConnector, Emailer)
Fanout pour écrire

Un workspace n'a pas de limite de readers ou de writers. Ils ne s'affichent pas sur le canevas : ce sont des entrées dans le Navigator.

3Un reader, plusieurs fichiers

Le paramètre du dataset source

Ctrl pour multi-sélectionner dans le navigateur de fichiers, ou Select multiple Folders/files, ou une liste séparée par des virgules (C:\FMEData\Data\Orthophotos\02-03-HI.tif,C:\FMEData\...). Ce paramètre est publié par défaut : l'utilisateur peut choisir plusieurs fichiers au runtime.

Tout est lu comme un seul feature type. Pratique pour des jeux découpés en tuiles et de même schéma, à traiter ensemble.

4Les chemins dynamiques

Directory and File Pathnames

Ce reader génère le chemin de chaque dataset avec une glob expression : une feature par chemin. On les envoie ensuite à un FeatureReader qui lit les fichiers.

Les jokers

Utiles quand on ne connaît pas à l'avance les chemins ou qu'on veut accepter facilement des datasets d'entrée : on met des jokers dans le dataset source.

5Fusionner les feature types

Quand fusionner

Beaucoup de feature types (tables, couches) de même schéma qui subissent le même traitement. À l'ajout du reader, option Single merged feature type. Après coup, on coche Merge Feature Types dans les paramètres.

Le filtre

Par défaut *, tout est lu. On accepte un nom exact, un joker ou une expression régulière pour plus de contrôle.

Après la fusion, le nom du feature type d'origine reste accessible dans fme_feature_type.

À retenir

  • Un workspace peut avoir autant de readers et de writers qu'on veut.
  • Un reader peut lire plusieurs fichiers : tout arrive dans un seul feature type.
  • Directory and File Pathnames plus FeatureReader, pour des chemins dynamiques.
  • Merge Feature Types applique le même traitement à beaucoup de couches.
  • fme_feature_type garde le nom d'origine après la fusion.

Beaucoup de fichiers, un seul traitement : voilà l'intérêt de FME.
