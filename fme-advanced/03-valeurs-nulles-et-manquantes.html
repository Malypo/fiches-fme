Valeurs nulles

Null, vide, manquant : que dire de rien ?

1Les définitions

Null
Dans FME, un état volontairement posé pour signifier que l'information n'existe pas. Ce n'est pas une erreur.
Vide (empty)
L'attribut existe mais n'a pas de valeur.
Manquant (missing)
L'attribut devrait exister mais n'est pas là. Par exemple après une jointure.
NaN
Un attribut numérique qui n'est pas un nombre.

2Les formes de rien

Dans les données

Tous les jeux de données n'ont pas de NULL et tous les formats ne le gèrent pas. On trouve un état qui indique le rien (NULL), une valeur qui l'indique (par exemple -999), un attribut vide, un attribut manquant, un NaN, un 0, ou une cellule raster en nodata (l'équivalent raster du null).

Les développeurs de FME ont identifié 15 façons de représenter le rien dans les données spatiales et tabulaires.

3Reconnaître les nulls

Le Tester

Le test Attribute has a value vérifie que l'attribut n'est ni nul, ni vide, ni manquant.

Le Matcher

L'option de comparaison des attributs différencie ou non vide, manquant et null. Sur Non, une feature avec un null peut correspondre à une avec un manquant. Sur Oui, elles ne correspondent que si c'est le même type de rien.

L'AttributeFilter

Il a des ports séparés pour vide, manquant et null.

4Écrire et joindre

À l'écriture

Si le format gère le NULL, le dataset en contient. Sinon, FME convertit vers la représentation la plus proche qui est gérée.

Dans les jointures

Quand une clé est nulle, il faut décider si la feature est rejetée ou jointe avec une clé nulle : un paramètre le précise. Certains transformers ont des paramètres propres aux nulls, lis leur documentation.

5Poser des nulls

La voie habituelle

L'AttributeCreator ou l'AttributeManager, qui ont une option pour mettre NULL. Les attributs conditionnels le gèrent aussi.

Le NullAttributeMapper

Il traite en masse les attributs : on teste les valeurs d'un ou de tous les attributs et on les convertit vers ou depuis null, ou vers une nouvelle valeur (par exemple null vers 0). Quand on passe d'un format sans NULL à un format avec, il faut mapper explicitement la valeur pour garder le null.

Si le writer ne sait pas lire le null, il le change automatiquement. Pas besoin de transformer, sauf pour mieux contrôler la sortie.

6Exercice : les parcs sans nom

Le problème

Les parcs doivent être triés par nom dans une Geodatabase, ceux sans nom en dernier. Mais les sans-nom arrivent toujours en premier. FME place par défaut NULL, MISSING et EMPTY en haut des colonnes triées (Visual Preview et Sorter).

La solution

NullAttributeMapper sur ParkName : si manquant, valeur ZZZ
Sorter alphabétique sur ParkName
RefParkId : si valeur -9999, mapper vers null

Pour écrire les features sans nom à part, un Tester après le reader filtre les nulls.

Le piège

Un null n'est pas un manquant ni un vide. Selon le Matcher, ils peuvent correspondre ou non. Et -9999 n'est un null que pour toi : il faut le mapper en vrai null.

À retenir

  • Null est un état voulu, vide et manquant sont des accidents possibles.
  • Le Tester teste « a une valeur », l'AttributeFilter sépare les trois cas.
  • Le NullAttributeMapper corrige en masse, comme transformer -9999 en null.
  • Chaque format gère le null à sa façon, FME convertit au plus proche.
  • Vérifie la documentation des transformers qui ont un paramètre pour les nulls.

Savoir nommer le rien, c'est déjà bien le traiter.
