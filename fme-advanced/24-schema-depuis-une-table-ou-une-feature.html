FME

Table de schéma

Schéma depuis une table ou une schema feature

1Les définitions

Schema feature
Une feature qui décrit un schéma : noms d'attributs, types, géométrie, dans une liste attribute{}.
SchemaMapper
Utilise une table de correspondance pour mapper les attributs entrants vers le schéma sortant.

2Les autres sources

Les trois cas

Une table de correspondance (fichier texte ou tableur) qui stocke la définition
Une schema feature créée par un FeatureReader
Une schema feature définie dynamiquement dans le workspace

En général le schéma vient du dataset source ou d'un autre dataset (par exemple une table).

3Un schéma dans une table

Le principe

Un fichier texte ou un tableur stocke le schéma de sortie (par exemple un Excel avec featureType, AttributeName, GeometryType...). On l'utilise en ajoutant un Resource Reader au format Schema (From Table) et en mappant les champs. Optionnel : Geometry et Attribute Sequence (l'ordre des attributs).

Le writer

Il utilise la ressource, et le SchemaMapper mappe les attributs entrants vers le schéma sortant. Avantage : pas besoin de modifier le workspace ni le dataset pour changer le schéma.

4Une schema feature

Depuis un FeatureReader

Source courante pour le dynamique. Quand on ne connaît pas le schéma à l'avance, on envoie un schéma au writer dynamique avec le port <Schema>. Exemple : une API renvoie une liste d'URLs de pièces jointes CSV : on veut les lire et les écrire dans un dossier local, sans connaître le schéma.

Le réglage

FeatureReader, Feature Type Name(s) : From file name(s), donc fme_feature_type porte le nom du fichier
Output Ports : Single Output Port, tout par <Generic>
Writer : nom du fichier CSV = fme_feature_type, Schema Source = Schema from Schema Feature

Le writer utilise le schéma de la feature issue du port <Schema> du FeatureReader, et sépare en fichiers CSV selon les noms de feature types.

Une schema feature construite

On construit à la main une schema feature avec des listes FME : les attributs de la liste définissent le schéma. Elle passe devant toute autre quand on la choisit comme source (Schema From Schema Feature).

5Les types de données FME

Caractère
fme_varchar(width), fme_char(width), fme_char
Entier
fme_uint8, fme_int16, fme_uint16, fme_int32, fme_uint32, fme_int64, fme_uint64
Numérique
fme_decimal(width,decimal), fme_real32, fme_real64
Date et heure
fme_datetime, fme_time, fme_date
Autres
fme_buffer, fme_boolean

6Exercice : un schéma Excel

Le besoin

À la suite de l'exercice précédent, il faut une troisième table. Plutôt que de modifier le workspace à chaque ajout, un Excel contient la définition du schéma : l'équipe de planification en est propriétaire sans toucher à FME.

Les étapes

Supprimer le dernier resource reader
Build, Add Reader as Resource, format Schema (From Table)
Writer, Schema Sources : le tableur (décocher FireHalls, inclus dans la source)
Ajouter un reader pour le nouveau feature type
Run

L'alternative

Creator
FeatureReader : Zone et Park (.tab), Fire All (.gml) ne peut pas être lu dans le même
Output port : Single Output Port <Generic>
Writer dynamique : generic plus schema, Schema source = Schema from Schema Feature

Pour éviter de créer plusieurs readers. Au run : deux schémas (aux attributs non exposés) et <Generic> (tous les features, attributs sources non exposés, visibles dans les colonnes). La méthode permet d'écrire les résultats de toute donnée lue par un FeatureReader sans modifier le schéma, ni SchemaMapper, ni SchemaScanner, et se combine avec un Generic writer ou plusieurs writers.

À retenir

  • Un schéma peut venir d'une table (Schema From Table), d'un FeatureReader ou d'une liste construite.
  • Avec une table, on change le schéma sans toucher au workspace.
  • Le port <Schema> du FeatureReader envoie le schéma au writer dynamique.
  • Schema Source = Schema from Schema Feature pour l'utiliser.
  • Les types FME : fme_varchar, fme_int32, fme_real64, fme_datetime...

Un schéma dans un tableur, et l'équipe métier est autonome.
