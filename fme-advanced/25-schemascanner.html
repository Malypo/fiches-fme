FME

SchemaScanner

Construire un schéma en cours de route

1Les définitions

Schéma
Le modèle de données : feature types, géométries permises, attributs et autres règles. Le plus critique : nom et type des attributs.
Schema drift
Les attributs et types de données peuvent être ajoutés, retirés ou modifiés.
SchemaScanner
Le transformer qui scanne les features et en tire le schéma : nom et type des attributs.

2À quoi ça sert

Le principe

Il évite les problèmes de standardisation du schéma et de dérive. Il donne une liste d'attributs (noms et types) : en aval, on peut manipuler le schéma, et au lieu d'un schéma fixe sur le writer, utiliser celui de la liste.

Les usages

S'assurer que le writer dynamique reçoit un schéma valide
Données entrantes au schéma inconnu, à vérifier contre des normes avant écriture
Modifier le schéma avant le writer
Exposer le schéma pour validation

Exemple : un dataset au schéma inconnu et changeant, dont on teste les attributs contre des exigences avant d'écrire en base.

3Le fonctionnement

La sortie

Le SchemaScanner scanne toutes les features ou un nombre précis, et peut exclure des attributs avec une expression régulière. Le résultat est une nouvelle feature de schéma par le port <Schema>. fme_schema_handling = 'schema_only' permet à un writer dynamique de la reconnaître. Pour garder les features d'origine : le port Output.

Les bonnes pratiques

Dans un workspace dynamique, sortir la schema feature avant les données : paramètre Output Schema Feature Before Data. Ignore Attributes Containing exclut ce qui est inutile. Le but : récupérer le schéma des datasets et créer des workflows flexibles.

Les paramètres par défaut

Exclut les attributs contenant fme_ ou multi_ du schéma, ainsi que les attributs de format. Ignore les attributs vides ou nuls. Détecte les dates (sinon une donnée non réglée est un nombre).

4La schema feature

Son contenu

Une liste attribute{} qui stocke noms et types : attribute{}.name, attribute{}.fme_data_type.

Les producteurs

Le SchemaScanner : la « meilleure estimation » de FME
Le FeatureReader : copie du schéma du dataset
Le reader Schema (Any Format)
L'AttributePivoter

Utilise le SchemaScanner pour scanner le schéma au milieu du workspace, après avoir lu et manipulé les données.

5Exercice : CSV avec une nouvelle colonne

Le but

Transformer des CSV, avec un schéma dynamique qui tient compte des changements faits dans le workspace.

Les étapes

Generate workspace dynamique (reader et writer en CSV), lancer et inspecter
AttributeManager : créer Hours (l'heure d'ouverture), supprimer Open et Close
SchemaScanner après : Output schema before data feature = Yes, les deux sorties vers le writer dynamique
Writer : Schema Source = Schema From Schema Feature (Only), Schema Definition Name = fme_feature_type_name

Hours doit être au-dessus de Open et Close dans l'AttributeManager, sinon ils sont supprimés avant. Si le CSV a un nouvel attribut non défini sur le feature type du reader, le writer l'inclut sans le modifier (le SchemaScanner le lit). Si le CSV n'a pas l'attribut Close, le workspace tourne mais avec une valeur incorrecte.

6Plusieurs datasets

Missing/Null/Empty Attribute

Ignore : retire la colonne sans valeur
Use default data type / Interpret Upstream Schema : inclut la colonne

Il ne s'applique qu'aux cas où tout le dataset est sans valeur pour un attribut.

L'exercice

Nouveau reader CSV connecté à l'AttributeManager, ou ajouter un fichier dans le reader dynamique
CSV file name = Day (attribut), une sortie par jour
SchemaScanner : Enable Group Processing, Group By Day, un schéma par jour
Missing/Null/Empty Attribute = Interpret Upstream Schema : les colonnes vides ont un type

Pour vérifier un schéma : Record of Information, attributs non exposés. L'attribut Schema Definition Name = fme_feature_type_name dit au writer quelle schema feature utiliser quand il en reçoit plusieurs. Si on lit plusieurs datasets et qu'on utilise le SchemaScanner avec ses réglages par défaut pour fournir un seul schéma, la sortie contient tous les attributs de tous les datasets.

À retenir

  • Le SchemaScanner donne le schéma de ce qui passe, nom et type des attributs.
  • Sors la schema feature avant les données pour un writer dynamique.
  • Le port <Schema> alimente le writer, le port Output garde les features.
  • Group By crée un schéma par groupe, Interpret Upstream Schema garde les colonnes vides.
  • Ignore Attributes Containing retire ce dont tu n'as pas besoin.

Le schéma se calcule en route : plus besoin de le deviner.
