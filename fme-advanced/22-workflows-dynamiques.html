FME

Dynamique

Des workspaces sans schéma défini

1Les définitions

Schéma
Le modèle de données : la structure du jeu de données.
Workflow dynamique
Un workspace « sans schéma » : il traite les données quel que soit leur schéma.
Static schema
Le schéma de la source est celui de la destination, défini dans le workspace.

2Statique ou dynamique

Le statique

Le schéma du writer peut s'éditer à la main mais doit être défini dans le workspace.

Le dynamique

Le workspace accepte n'importe quelle entrée et un nouveau schéma de sortie venant de plusieurs sources : n'importe quel dataset entrant, un dataset externe, une table de correspondance, ou défini dans le workspace. Le schéma n'a pas besoin d'être défini.

Certaines fonctions ne marchent qu'avec un schéma fixe : par exemple un attribut doit être exposé pour qu'un transformer y accède.

3Lecteurs et writers dynamiques

Le reader dynamique

Proche des Merge Parameters : les feature types entrent librement et les données sont lues quelle que soit la géométrie ou les attributs.

Le writer dynamique

Tous les attributs et géométries sont écrits, même sans être prédéfinis dans un feature type de writer.

4Quand l'utiliser

Les usages

Une transformation simple sur toutes les données, quel que soit leur schéma (découpe, transformation de coordonnées)
Un schéma de source imprévisible ou mal défini
Une transformation ad hoc sur beaucoup de jeux différents (moyenne de quelques attributs)
Une maintenance à long terme du workspace

Un workspace dynamique ne lira ni n'écrira pas toujours tout format de données.

5Générique ou dynamique

Je connais le format, je connais les feature types et les attributs
Statique.
Je ne connais pas le format, mais je connais feature types et attributs
Generic plus statique.
Je connais le format, je ne connais pas les feature types, mais je connais les attributs
Fanout.
Je ne connais pas le format ni les feature types, mais je connais les attributs
Generic plus fanout.
Je connais le format et ne connais pas les attributs
Dynamique.
Je ne connais ni le format ni les attributs
Generic plus dynamique.

6Créer un workspace dynamique

Generate Workspace

Build, Generate Workspace, puis Workflow Options : Static Schema (par défaut) ou Dynamic Schema. On peut ne rendre dynamique que le reader ou que le writer. On peut aussi basculer en changeant le paramètre du feature type.

Reader seul

À l'ajout, Workflow Options, Single Merged Feature Type (comme Merge Type sur le feature type du reader). Si on ajoute un feature type individuel puis qu'on coche Merge Feature Type, on utilise le schéma d'origine de ce feature type : les autres, aux attributs différents, sont lus mais non exposés.

Writer seul

Add Writer, Add Feature Type(s), Dynamic (Advanced). Mode Automatic : les attributs prennent la définition de ce qui est connecté, un changement de source n'a pas d'effet. Mode Dynamic : si le dataset source change, la définition vient des données lues, peu importe ce qui est connecté.

À quoi ça ressemble

Un seul feature type pour le reader (nommé <All>) et pour le writer (nommé <Dynamic>). FME lit tout par un seul feature type, et le writer redivise les couches avec leurs attributs et géométries d'origine. On peut changer le dataset source (au bon format) et la sortie en est le miroir. Pas de souci de géométrie non supportée ou d'entrée inattendue. Avec les Generic reader et writer, on lit n'importe quel format et on crée un double dans le format voulu.

Le mode Automatic du writer est plus utile quand ce sont les transformers avant qui comptent.

7Exercice : une gdb quelconque

Le but

Traduire n'importe quelle Geodatabase vers le format choisi. Avant, chaque sortie contenait tous les attributs de la source, et seule la community map était gérée.

Les étapes

Generate Workspace
Writer Generic (shapefile par défaut)
Workflow option Dynamic
Run, puis View Written Data (il faut choisir le dataset à voir)
Changer la base, vider Feature Types to Read, relancer

À retenir

  • Dynamique : le schéma vient de la source, pas du workspace.
  • Generate Workspace, Workflow Options, Dynamic Schema crée reader et writer dynamiques.
  • Le reader s'appelle <All>, le writer <Dynamic>.
  • Automatic suit ce qui est connecté, Dynamic suit le dataset source.
  • Generic gère le format inconnu, dynamique gère les attributs inconnus.

Un workspace qui s'adapte à ses données : moins de maintenance, plus de sérénité.
