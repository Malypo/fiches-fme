FME

Archives et web

Lire et écrire des zip et des données en ligne

1Les définitions

Archive
Un fichier qui stocke des jeux de données à traiter comme une seule unité.
Web connection
Une connexion à un service web, créée une fois et réutilisable dans les dialogues de lecture.
Connector transformer
Un transformer qui copie un fichier depuis ou vers un service web, sans lire les données lui-même.

2Lire et écrire des archives

Les formats archive

7z, 7zip, rar, rvz, tar, tar.bz2, tar.gz, tgz, zip

Les readers et writers savent travailler avec des fichiers compressés. Ça marche pour les jeux de données basés sur un fichier comme sur un dossier.

Les fichiers compressés seuls

bz2
gz

Écrire un zip

Le plus simple : écrire l'extension .zip dans le dataset de sortie, ou utiliser le bouton à côté du dataset. Avec TCL ou Python, on peut ensuite retrouver le fichier écrit pour le déplacer ou le téléverser.

3Lire un jeu de données web

La sélection d'URL simple

Le plus simple : mettre l'URL dans le paramètre du dataset source. L'astuce est de forcer le service à donner un lien direct plutôt que son interface. Pour Dropbox, on force le paramètre dl à 1. Un dossier doit être compressé en un seul zip pour que FME le lise depuis le web. Si une authentification est nécessaire, les readers ont un paramètre pour ça.

C'est la méthode la plus simple, mais pas la meilleure. Seul un reader peut utiliser une URL, un writer ne peut pas écrire vers une URL.

4Les web connections

Les créer

Utilities, FME Options, Web Connections. Les plus courantes : Amazon S3, Autodesk A360, Box, Dropbox, FME Flow, Google Drive, HDFS, Microsoft OneDrive. Il faut s'authentifier à chaque nouveau service. Les connexions sont ensuite accessibles depuis le dialogue Add Reader ou le FeatureReader.

Les mises à jour

Les packages FME permettent de mettre à jour les web connections en dehors du cycle de sortie annuel de FME.

5Les connector transformers

Leur rôle

Ils copient un fichier choisi et ajoutent son contenu dans un attribut (par exemple du XML), ou le téléchargent sur le disque local. Ils peuvent aussi téléverser ou supprimer un fichier. Un Creator peut déclencher la lecture.

Ce n'est pas fait pour lire

Lire les données reste le rôle des readers. On s'en sert pour télécharger, pour récupérer une liste de fichiers et les lire avec un FeatureReader, et surtout pour envoyer des données écrites vers le web.

Écrire vers le web

Les writers n'ont pas l'option de sélection de fichier depuis le web. La meilleure solution : écrire avec un FeatureWriter, puis utiliser un connector transformer pour transférer le résultat.

6Exercice : neige et routes

Le scénario

Joindre des données de chute de neige à des routes, puis écrire le résultat sur un FTP pour d'autres utilisateurs.

Les étapes

Reader Autocad avec l'URL en source
DatabaseJoiner pour lire l'Excel et le joindre
FeatureWriter vers un zip
FTPCaller connecté au FeatureWriter

Le nom du fichier peut se construire avec l'attribut _dataset du FeatureWriter, @ReplaceRegularExpression et @ReplaceString. Dans l'URL, @UUID() génère un emplacement unique à chaque exécution : ftp://ftp.safe.com/incoming/training/@UUID()RoadSnowfall.zip

Le KMLStyler peut préparer le KML pour la visualisation.

Le piège

Les connector transformers ne sont pas des readers. Pour lire de vraies données sources, passe par un reader ou un FeatureReader.

À retenir

  • Écrire .zip dans le dataset suffit à créer un zip.
  • Un reader peut lire une URL, mais un writer ne peut pas écrire vers une URL.
  • Les web connections se créent dans FME Options et servent aux readers et au FeatureReader.
  • Pour envoyer des données vers le web : FeatureWriter, puis connector transformer.
  • @UUID() évite d'écraser un fichier déjà présent sur le serveur.

Un zip, un lien, un connecteur : tes données voyagent toutes seules.
