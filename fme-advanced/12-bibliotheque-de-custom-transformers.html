Embedded, linked et versions

1Les définitions

Embedded
La définition est stockée dans le workspace. Seul ce workspace y accède.
Linked
La définition est dans un fichier séparé (.fmx). Tout workspace peut y accéder.
Insert mode
Le contrôle de l'auteur sur l'état initial d'une instance placée.

2Embedded ou linked

Embedded

Avantages : facile à gérer (pas de fichier externe), pratique pour ranger un workspace, utile pour le traitement parallèle, on partage en donnant une copie du workspace. Inconvénients : le partage et la réutilisation sont plus complexes, difficile à maintenir à plusieurs.

Linked

Avantages : fonctionnalités avancées comme les boucles, plus facile à éditer, plus facile à partager (plusieurs auteurs pointent vers le même fichier, mise à jour simplifiée), symbole propre (une petite chaîne). Inconvénient : plus compliqué à gérer avec des fichiers .fmx externes.

Les deux apparaissent dans la transformer gallery et le Quick Add.

3Créer un linked

L'export

Tous les custom transformers commencent embedded. Pour une définition externe : Export as Custom Transformer dans le menu, puis confirmer nom, catégorie, etc.

L'insert mode

Embedded Always : pas de bascule possible
Embedded by Default : l'utilisateur peut basculer vers linked
Linked by Default : bascule possible
Linked Always : pas de bascule

Le fichier FMX stocke la définition. Avec un mode embedded, la définition est copiée dans le workspace à la pose d'une instance. L'auteur contrôle ainsi comment les utilisateurs s'en servent.

Lequel choisir

Embedded Always pour des utilisateurs moins expérimentés (leurs changements n'affectent personne) ou pour personnaliser. Linked Always quand les utilisateurs partagent le custom et que la mise à jour doit toucher tout le monde : on fait confiance aux utilisateurs.

4Mot de passe, emplacement, Flow

Mot de passe

Protège le custom : impossible de l'éditer ou d'ouvrir le fichier source dans un éditeur de texte. Utile pour le vendre sans craindre la copie.

Où sauvegarder

FME a un dossier d'installation spécifique. Ailleurs, on ne le retrouve pas sauf en ajoutant le chemin dans Utilities, FME Options, Default path.

Sur FME Flow

Il faut publier le custom transformer en plus du workspace. Soit un upload dans un repository (les autres workspaces l'utilisent en réglant manuellement leurs paramètres source), soit un dossier de ressource partagée, meilleur si on veut une large disponibilité.

5Changer de type, imbriquer

Embedded vers linked

Le custom doit déjà être exporté. La définition embedded est fermée et le transformer pointe vers la définition linked. Ça ne marche que si tu n'as pas modifié le transformer embedded.

Linked vers embedded

Le FMX est copié dans le workspace. Avec plus d'une instance, FME demande si on les bascule toutes.

On peut mettre un custom dans un autre sans restriction de type ni de niveau. Pour le débogage, cherche les bugs dans un custom embedded avant de l'exporter : le caching et les breakpoints ne marchent pas dans un transformer exporté.

6Les versions

Le principe

Le versionnage ne concerne que les définitions externes (FMX, linked). Un FMX peut contenir plusieurs versions du même custom. L'auteur peut revenir à une définition précédente, et créer une définition par version de FME pour rester compatible avec les anciennes.

Créer une version

Au bouton Save, un choix : nouvelle version (active le versionnage) ou écraser. Une nouvelle version ne crée pas un autre fichier FMX. Pour en créer une autre, il faut fermer puis rouvrir le fichier : le bouton Save n'enregistre que la version ouverte.

Versions et FME

Chaque version est associée à une version de FME. Modifier un transformer créé dans une version plus ancienne le rend incompatible avec les versions plus anciennes.

Mettre à jour

Afficher la version : Utilities, FME Options, Workbench, Transformers, Display transformer version. Quand une nouvelle version existe, clic droit sur le transformer, upgrade to latest version, ou via le Navigator. Si tu es en version 1 et que l'auteur est en version 4, tu auras la dernière version compatible avec ta version de FME.

7Exercice : longueur moyenne

Le but

Snapper (end point snapping)
LineCombiner end noded
LengthCalculator
StatisticsCalculator (mean)

Un transformer qui calcule la longueur moyenne des lignes. Custom AverageLengthCalculator depuis LengthCalculator et StatisticsCalculator, entrée renommée Line, sortie ajoutée, AttributeRenamer vers AverageLength.

L'export et la mise à jour

File, Export as a custom transformer (linked par défaut). La couleur change dans l'onglet principal. Clic droit, embed : la couleur change encore, et si on l'ouvre et modifie, on ne peut plus revenir. À la suppression, cocher oui pour supprimer aussi la définition. Pour la v2 : un GeometryFilter avant le LengthCalculator, avec une sortie pour l'utilisateur, Save en nouvelle version. Dans l'onglet principal, le bouton refresh de la gallery découvre la version, puis upgrade.

Le piège

Une définition embedded reste dans le workspace même sans usage. Pour la supprimer avec le transformer, coche oui à la suppression.

À retenir

  • Embedded dans le workspace, linked dans un fichier .fmx partagé.
  • L'insert mode contrôle si l'utilisateur peut basculer entre les deux.
  • Le versionnage ne marche que pour les linked, plusieurs versions dans un seul FMX.
  • Pour créer une nouvelle version, ferme puis rouvre le fichier.
  • Sur FME Flow, publie le custom avec le workspace, en dossier partagé de préférence.

Une bibliothèque bien rangée, et ton équipe n'a plus à refaire deux fois le même transformer.
