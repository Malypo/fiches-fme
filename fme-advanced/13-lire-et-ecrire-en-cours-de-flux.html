FeatureReader, FeatureWriter et connecteurs

1Les définitions

Workflow transformer
Un transformer qui lit ou écrit des données en plein milieu du flux, à la place d'un reader ou writer.
Initiator
La feature qui entre dans le FeatureReader et déclenche la lecture.
TempPathnameCreator
Crée un dossier temporaire supprimé à la fin du workspace.

2Les workflow transformers

Les quatre familles

FeatureReader, FeatureWriter : formats FME
DropboxConnector, GoogleDriveConnector, SalesforceConnector, SlackConnector : services web
AttributeFileReader, AttributeFileWriter : lire et écrire des attributs
JMSSender/Receiver, SQSConnector, TCPIPSender/Receiver : paquets de données

AttributeFileReader lit le contenu d'un fichier dans un attribut (texte ou blob binaire). AttributeFileWriter écrit le contenu d'un attribut dans un fichier.

L'avantage : lire ou écrire au milieu d'un flux, pas seulement au début ou à la fin. Les connecteurs exposent déjà les bons paramètres, ce qui est plus rapide et facile que d'appeler l'API directement avec le HTTPCaller. Pour envoyer des données sensibles de toute taille vers l'écosystème AWS, c'est le SQSConnector. Si un appel d'API renvoie un fichier binaire dans _response_body, l'AttributeFileWriter l'enregistre en local.

3Le FeatureReader

Le déclenchement

Toute feature qui entre par l'initiator déclenche la lecture. Le dataset est lu autant de fois qu'il y a de features dans l'initiator.

Les ports de sortie

Un port par feature type (par défaut)
Single Output Port : tout par <Generic>
<Schema> : une feature de schéma par feature type
<Generic> : features sans port nommé
<Rejected> : features invalides (dataset inexistant, filtre spatial sur feature sans géométrie)

Le port de l'initiator renvoie l'original avec l'attribut _matched_records (nombre de features lues pour cet initiator). Avec Single Output Port, on retrouve le feature type avec fme_feature_type.

Dataset par attribut

Cas typique : un shapefile avec l'index des orthophotos, et un FeatureReader GeoTIFF qui lit le fichier indiqué par un attribut. S'il y a plusieurs features avec un chemin de dataset, le paramètre Dataset du FeatureReader contrôle ce qui est lu.

Le filtre spatial

Basé sur la géométrie. On peut aussi exécuter des requêtes sur une base de données (SQL ou Cypher).

4Le FeatureWriter

Tout dans un dialogue

Tous les paramètres et la définition du schéma d'un writer sont dans un seul dialogue. Le bouton plus ajoute des feature types. Le port de sortie se définit à la main ou s'ajoute en connectant l'entrée.

Les sorties

Elles se connectent à d'autres transformers. Les features du FeatureWriter portent l'attribut _dataset, le chemin du fichier écrit.

Avec le TempPathnameCreator

Cas courant : écrire un dataset temporaire avant de le téléverser. Le dossier est supprimé après le run (pas d'accumulation), sur FME Form comme sur FME Flow. Sur FME Flow, le paramètre FME_SHAREDRESOURCE_TEMP écrit dans le stockage temporaire, nettoyé selon la config.

5Exercice : les orthophotos

Le scénario

Un dossier d'orthophotos GeoTIFF dont on extrait des rasters individuels couvrant plusieurs quartiers du centre-ville. On configure un FeatureReader avec plusieurs initiators, un FeatureWriter et un connector transformer.

Le FTPCaller n'accepte pas Web Connection comme type d'authentification, seulement None/Anonymous, Password et ssh-agent/pageant (SFTP seulement).

À retenir

  • FeatureReader et FeatureWriter lisent et écrivent n'importe où dans le flux.
  • Une feature dans l'initiator déclenche une lecture complète du dataset.
  • Les ports de sortie du FeatureReader : feature types, <Generic>, <Schema>, <Rejected>.
  • Le TempPathnameCreator évite l'accumulation de données temporaires.
  • Un connecteur est plus simple que le HTTPCaller pour parler à un service web.

Lire ou écrire quand tu veux, pas seulement au début ou à la fin.
