WorkspaceRunner, wizard et traitement parallèle

1Les définitions

Batch processing
Traiter plusieurs jeux de données avec le même workspace. Pas toujours plus rapide : à tester.
Traitement parallèle
Exécuter plusieurs actions simultanément, dans des processus séparés.
Groupe artificiel
Un groupe créé à la main quand les données n'ont pas d'identifiant de groupe.

3Le WorkspaceRunner

Le principe

Un transformer qui lance un autre workspace. On peut chaîner plusieurs workspaces ou les lancer en parallèle, avec le reader Directory and File Pathnames. Le workspace parent contient le WorkspaceRunner, le worker (helper) est celui à traiter en lot.

Les réglages

Le paramètre FME workspace pointe vers le helper. Source File reçoit path_windows, créé par le reader Directory and File Pathnames. Wait for Jobs to Complete attend la fin d'un job avant de démarrer le suivant, pour éviter plusieurs processus FME en concurrence. Maximum Number of Concurrent FME Processes (jusqu'à 7) quand l'ordre n'importe pas : ils se voient dans l'onglet Details du Gestionnaire des tâches. FME.EXE exécute le parent, les helpers sont des processus séparés de Workbench et du Data Inspector.

Exemple : chaque semaine de nouvelles photos, on crée un parent qui pointe vers le dossier, sans changer la source du helper. Le helper lit les tuiles d'orthophotos, les découpe aux quartiers et les écrit avec une combinaison tuile et quartier.

4Le Batch Translation Wizard

Où et pourquoi

Menu Run, Batch Translation. Traitement immédiat ou création de fichiers batch. Il traite beaucoup de datasets dans le processus courant et produit des sorties séparées. S'il est grisé (Deploy, Batch Translation), le workspace n'a pas de dataset source ou de destination défini.

Le wizard

L'utilisateur indique entrées, sorties et autres réglages. Si ce n'est pas immédiat, FME crée un batch (fichier .tcl) et un .bat à lancer plus tard, même en dehors de FME Workbench.

5Le parallèle avec un custom transformer

Où il agit

Sur une sous-partie du workspace, que l'auteur contrôle par un custom transformer. Les features sont groupées par valeur d'attribut (comme un transformer à Group By), et chaque groupe va dans un processus séparé. Sur FME Flow, on peut aussi utiliser plusieurs engines. Utile sur les machines puissantes (plusieurs processeurs et cœurs).

Les niveaux

Dans le Navigator du custom, groupe Data processing. Chaque niveau fixe le nombre de processus relatif au nombre de cœurs. Minimal : 2 processus FME sur une machine quatre cœurs. Extrême : 8. Ce nombre est un maximum à un instant donné : 20 groupes sur quatre cœurs, 4 tournent à la fois.

Les groupes

Le paramètre demande un attribut. On publie ce paramètre (et un autre pour le mode Complete Groups) pour les rendre disponibles dans le custom : Group By et Complete Group.

Quand c'est efficace

Peu de groupes, chacun avec beaucoup de traitement
Beaucoup de petites tâches déléguées ailleurs (par exemple le HTTPCaller)

Moins efficace avec beaucoup de petits groupes. Les features de groupes différents ne peuvent pas être liées. Le custom divise en groupes, traite chacun comme une action séparée, puis recombine.

Les groupes artificiels

Sans identifiant, on crée un attribut avec le ModuloCounter ou le RandomNumberGenerator. Vise un nombre de groupes proche de l'optimum de ta machine.

6Exercice : bâtiments OpenStreetMap

Le sujet

Valider des bâtiments OSM contre les jeux de la ville. Les données OSM sont issues du crowdsourcing : beaucoup de bâtiments n'ont pas d'adresse. On utilise le code postal pour les groupes.

Les étapes

Custom transformer de PointOnAreaOverlayer (où vient le code postal) au dernier transformer
SubstringExtractor : les trois premiers caractères du code postal
Parallel processing level : Moderate
Group By sur le BuildingValidator

Un reader ne peut pas être dans un custom transformer (seulement un « input »). Désactiver le data caching et arrêter aux breakpoints.

Le correctif

Plus de bâtiments sans zone qu'avant : le reader MapInfo ne donne pas le même préfixe de code postal dans chaque processus. Solution : assigner le code postal à chaque zone, ou donner à chaque processus ses propres données de zonage, en remplaçant le reader par un Creator et un FeatureReader dans le custom.

17 groupes, c'est 17 processus : le temps pèse. Moderate donne un processus par cœur. Pour vérifier le parallélisme : chercher les processus FME objects Worker dans le Task Manager, l'Activity Monitor ou le System Monitor.

À retenir

  • Le WorkspaceRunner lance un helper pour chaque fichier, avec un maximum de processus concurrents.
  • Wait for Jobs to Complete évite plusieurs processus à la fois.
  • Le Batch Translation Wizard traite beaucoup de datasets d'un coup.
  • Le parallèle passe par un custom transformer, avec un Group By et un niveau de parallélisme.
  • Peu de gros groupes, ou beaucoup de petites tâches déléguées : c'est là que le parallèle gagne.

Plusieurs coeurs, plusieurs processus : à toi de leur donner du travail.
