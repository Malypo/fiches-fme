FME

Mode générique

Lire et écrire n'importe quel format

1Les définitions

Generic reader
Un reader qui lit des datasets de formats différents dans le même workspace.
Generic writer
Un writer qui réachemine la sortie vers n'importe quel writer FME, dynamiquement, à l'exécution.
Unexpected Input Remover
Filtre les données entrantes contre la liste des feature types autorisés.

2Le Generic reader

Ce qu'il accepte

Un fichier, plusieurs fichiers, des dossiers, des URLs, des bases de données. Si le format demande un dossier en entrée, le Generic reader retire le nom de fichier du chemin. Le format est réglé sur Guess from extension par défaut : attention, la même extension peut poser problème.

Autre approche

Mettre le dataset source sur un paramètre publié (l'utilisateur précise le format du reader) et utiliser un ParameterFetcher pour récupérer le nom du format.

3Les limites du reader

Un reader supplémentaire

Parfois il faut préconfigurer des paramètres propres à un format (par exemple une connexion à une base). On ajoute un reader (ou un schema reader) : le premier est le Generic avec tous les feature types, le second peut n'en avoir aucun et transmet les réglages au Generic quand il utilise ce format. Le Generic cherche un autre reader qui correspond (selon l'extension). Ça ne marche que pour les formats basés sur des fichiers.

Les feature types

L'Unexpected Input Remover supprime tout ce qui n'est pas défini. Exemple : un workspace avec une couche trafficSignals Autocad, puis un fichier MicroStation dont les données sont sur une autre couche : le Router et l'Unexpected Input Remover les suppriment de la traduction. Chaque dataset doit avoir ses couches définies comme feature types. Pour tout autoriser : Merge Feature Types dans les propriétés du feature type du reader.

Les paramètres de format

Le Generic ne permet pas de régler le comportement d'un format précis. On combine avec Add Reader as Resource : il apparaît dans le Navigator, dans Workspace Resources.

Le Generic gère des formats flexibles et des couches flexibles (avec un Merge Filter), mais les datasets doivent avoir le même schéma d'attributs. Pour un schéma flexible : traduction dynamique.

4Le Generic writer

Le principe

Le nom du writer est un argument. La transformation et la traduction se définissent indépendamment du format de sortie : utile quand on connaît les schémas et la transformation mais pas la sortie. On l'ajoute comme un writer normal, format Generic, et FME détermine le format à partir de la destination. Format par défaut : Parameters, Output format, ou dans le Navigator, paramètres du writer. L'utilisateur peut aussi le choisir au runtime.

La géométrie

Toute la gamme de géométrie et d'attributs. On peut écrire plusieurs géométries dans un seul feature type de sortie. Si le vrai writer (par exemple Shapefile) ne le permet pas, FME crée des feature types séparés avec un suffixe de géométrie.

Les feature types de sortie

Généralement définis explicitement. Le writer a un réglage Dynamic Schema : FME base les définitions de sortie sur le schéma des readers du workspace.

Plusieurs formats

Pour préconfigurer des paramètres propres à un format, on ajoute un writer, ce qui force un Multiwriter (writer 1 : Generic avec tous les feature types, writer 2 : sans feature type, pour les réglages propres au format).

Un seul format de sortie par Generic writer : le publier en paramètre. Pour plusieurs formats, un writer dédié par format, avec un Tester ou TestFilter pour router. Flexible en format, mais il faut un feature type fanout pour être flexible en couches, et le schéma d'attributs doit être le même (sinon, traduction dynamique).

5Exercice : l'utilisateur choisit le format

Le but

Traduire le Community Mapping vers le format choisi par l'utilisateur, zippé, avec un workspace utilisable sans passer par toi.

Les étapes

Reader en single merged feature type, paramètre utilisateur pour choisir les tables (Features to Read)
Writer Generic (shapefile par défaut), définition automatique
Supprimer le paramètre du dataset source (toujours la même gdb)
Nouveau paramètre Choice, import depuis le format du writer, lié au paramètre Output format
Fanout sur fme_feature_type dans le nom du feature type du writer

Attention : en FME 2025.1, bug de géométrie. Il faut aller dans User Attributes, passer en manuel et régler la Spatial definition sur fme_any (une géométrie par sortie).

Le piège

Si le dataset change de format et que les couches n'ont pas les mêmes noms, l'Unexpected Input Remover supprime tout. Pense à Merge Feature Types.

À retenir

  • Generic reader et writer libèrent des restrictions de format.
  • Un Generic reader a besoin que les couches soient définies, ou fusionnées avec Merge Feature Types.
  • Un reader ou writer supplémentaire transmet les réglages propres à un format.
  • Le Generic writer écrit un seul format par run, à publier en paramètre.
  • Flexible en format et en couches, mais pas en schéma d'attributs.

Un workspace, tous les formats : le rêve de toute géomaticienne.
