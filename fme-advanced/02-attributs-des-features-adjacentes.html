FME

Features adjacentes

Utiliser la feature précédente ou suivante

1Les définitions

Feature adjacente
La feature qui précède ou suit la feature courante dans le flux.
Valeurs cumulées
Des valeurs qui s'additionnent au fil du temps : février vaut janvier plus février.

2Le principe

Pourquoi c'est utile

Une feature FME est normalement autonome : tout ce dont elle a besoin, elle l'a, et elle ne se rapporte pas aux autres. Les attributs adjacents permettent de s'appuyer sur la feature d'avant ou d'après.

L'exemple des précipitations

Les chiffres s'accumulent sur l'année. Le chiffre mensuel est donc la valeur du mois moins la valeur du mois précédent, soit la feature [-1].

3Les activer

Où le régler

Case Enable Adjacent Feature Attributes dans l'AttributeCreator ou l'AttributeManager. On choisit combien de features précédentes ou suivantes sont disponibles.

Les utiliser

@Value(Precipitation) - @Value(feature[-1].Precipitation)

Dans l'éditeur de texte ou d'arithmétique, feature[-x] donne l'attribut d'une feature voisine, avec x positif ou négatif.

Le coût

Stocker les features adjacentes utilise un peu plus de ressources, mais c'est relativement mineur (ça dépend du nombre de features et d'attributs conservés).

4Les valeurs manquantes

Que se passe-t-il au bord

La première feature n'a pas de précédente. Les deux transformers ont une option pour traiter les valeurs manquantes, nulles ou vides, pour la feature courante comme pour les adjacentes.

Dans l'exercice

Valeur par défaut 0 pour le manquant, sinon janvier n'aurait pas de valeur à soustraire. Avec No substitution, on peut créer une valeur manquante.

5Exercice : précipitations mensuelles

La méthode

Janvier = 168
Février = 273 - 168 = 105
Mars = 387 - 273 = 114

Les étapes

Reader Excel, puis AttributeManager avec Enable Adjacent Feature Attributes et un nombre de précédentes égal à 1. Valeur par défaut 0. Ouvrir l'éditeur arithmétique sur Precipitation avec la formule ci-dessus.

L'erreur à éviter

Écraser Precipitation donne un résultat faux, car le calcul utilise la nouvelle valeur et non l'originale. Il faut créer un nouvel attribut MonthlyPrecipitation avec la même formule.

Le piège

Si tu écrases l'attribut dans la même opération, la feature adjacente utilise déjà la nouvelle valeur. Crée un nouvel attribut pour garder l'original.

À retenir

  • Une feature FME est autonome, sauf si on active les attributs adjacents.
  • feature[-1] donne la précédente, un nombre positif donne la suivante.
  • On le règle dans l'AttributeCreator ou l'AttributeManager.
  • Penser au bord : une valeur par défaut évite les manquants sur la première feature.
  • Écris le résultat dans un nouvel attribut.

Regarder la voisine : parfois c'est tout ce qu'il faut pour un calcul.
