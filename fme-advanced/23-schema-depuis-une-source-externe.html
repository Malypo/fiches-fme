Schéma externe

Feature types, attributs et géométrie dynamiques

1Les définitions

Schema Sources
Le paramètre du feature type du writer qui dit où chercher le schéma de destination.
Resource reader
Un reader qui renvoie le schéma d'un dataset mais pas ses données.

2Les feature types dynamiques

Trois composants

Feature type
Attributs
Géométrie

Dans le reader, Merge Feature Type reste coché (le décocher coupe tout le comportement) et le Merge Filter contrôle les feature types lus. Dans le writer, on règle deux composants sur trois : le nom du feature type et la source des attributs.

Le nom

Un feature type statique prend une valeur fixe ou un attribut (fanout). En dynamique, le nom est fme_feature_type, qui garde le nom d'origine : FME recrée les feature types de la source. On peut utiliser un autre attribut : à l'exécution, FME cherche le même nom dans chaque schema source et utilise le schéma de cette table pour attributs et géométrie.

L'exigence

Une définition dynamique n'est pas un fanout. Le fanout crée des couches depuis une définition statique, le dynamique va chercher la définition ailleurs : le nom du feature type doit correspondre à une couche du schéma source, sinon FME supprime les données.

3Les sources de schéma

Le défaut

Le schéma du writer est défini par le dataset source. Le paramètre Schema Sources permet de le changer : structure d'un dataset entièrement différent, ou chaque composant. N'importe quel dataset de reader, dans n'importe quel format (le writer prend la structure, pas le format).

Les resource readers

Build, Readers, Add Reader as Resource : il apparaît dans Workspace Resources du Navigator. On n'a besoin que du schéma, pas des données.

Pourquoi un schéma externe

Respecter une norme fixe. Si le schéma du dataset change, le workspace l'utilise automatiquement sans mise à jour manuelle. Les données écrites doivent correspondre à la ressource : SchemaMapper ou une table de correspondance externe pour réconcilier.

4Les attributs

Le nom de définition

Le Schema Definition Name remplace la définition des attributs. Il peut être une valeur fixe (tous les feature types ont la même définition) ou un attribut : l'un définit le nom du feature type et l'autre un feature type qui fournit le schéma.

Un exemple

On écrit des parcs vers une Esri Geodatabase. Le nom de la table est l'attribut NeighborhoodName, et le schéma vient d'un Excel ajouté comme Resource Reader. Si NeighborhoodName vaut Strathcona, le writer cherche l'onglet Strathcona. Si on met Parks dans Schema Definition Name, les attributs sont écrasés et c'est la table Parks qui est utilisée : l'onglet Strathcona n'a même plus besoin d'exister (il ne sert que de nom).

Ajouter un attribut

Onglet User Attributes du writer : l'attribut est ajouté à toutes les sorties du feature type dynamique.

Supprimer un attribut

Dans la Schema Definition dialog dynamique, le bouton « … » ouvre le dialogue et on choisit l'attribut du schéma source. Attributes to Remove.

5La géométrie

Les modes

Statique : choisie dans la définition spatiale du writer
Dynamique : choisie à la main, selon la première feature, ou selon la définition du schéma choisi

La géométrie permise dépend du format. Si le reader fournit le schéma, la géométrie permise copie celle du dataset source. Si Schema Sources change, c'est celle du nouveau dataset. Si la géométrie écrite diffère du schéma et que le format ne supporte pas plusieurs types, FME supprime la donnée.

Fixe ou première feature

Même en dynamique, l'auteur peut remettre la géométrie sur une valeur fixe : elle remplace celle du schéma source. Avec First Feature, l'auteur n'a pas besoin de savoir à l'avance quelle géométrie le writer recevra ni ce que le schéma permet.

6Exercice : le nouveau community map

Le contexte

Le service d'urbanisme veut un nouveau jeu de données communautaire, avec les nouvelles données mais le schéma existant quand c'est possible, en GML (standard ouvert). Deux sources : les casernes de pompiers (GML) et les parcs de la ville (MapInfo TAB). Les parcs sont déjà dans la community map, mais en polygones et non en points. Les casernes sont nouvelles.

Les étapes

Generate Workspace (Dynamic Schema)
Reader en single merged feature type, annotations pour les distinguer
Connecter le nouveau reader au feature type du writer existant
Ressource reader sur la community map : Navigator, Workspace Resources
Properties du writer, Schema Sources : Community Map (Resource) et Fire Halls (inexistant dans la ressource)
GML accepte toutes les géométries
Supprimer un attribut : Attributes to Remove (impossible à sélectionner car il vient d'une ressource)
Ajouter LastUpdatedBy dans User Attributes

Au run, deux couches aux attributs différents. Les parcs ont des valeurs manquantes car il n'y a pas de mapping entre le nouveau et l'ancien schéma.

À retenir

  • Un schéma : feature type, attributs, géométrie.
  • Le nom du feature type doit exister dans la schema source, sinon les données sont supprimées.
  • Schema Sources choisit d'où vient le schéma, souvent un Resource Reader.
  • Schema Definition Name écrase la définition des attributs.
  • User Attributes ajoute, Attributes to Remove retire (sauf si le schéma vient d'une ressource).

Le schéma vient d'ailleurs, et le workspace suit sans rechigner.
